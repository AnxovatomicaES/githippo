## 3.9.2: fixes from three independent reviews (access control, content safety, setup and git)

Three separate code reviews went through githippo: the multi-user and remote server, the layer that screens what gets saved (secrets guard, injection screen, parsers, hooks), and what githippo does to a machine and a vault. Every finding was reproduced before it was fixed, and the fixes have regression tests (`test/report5*.test.js`), run against the 3.9.1 code to confirm they fail there. **If you run a team vault or the remote server, upgrade: one of these is critical on macOS and Windows hosts.**

### Access control and the remote server
- **Critical (macOS and Windows disks): a user could reach folders their rules deny.** Those filesystems fold `ſ`, `ß` and `ﬁ` like `s`, `ss` and `fi`; the permission check did not, so with the rules `:write,finance:none` the path `uſers/bob/inbox.md` read, overwrote and planted files in Bob's private folder, and `ﬁnance/q4.md` reached the denied folder. Paths are now folded the way those filesystems fold them.
- **`maintain` leaked other users' private notes** to anyone with a catch-all write rule (their lines, paths and note titles, including into the shared `index.md`). The report now covers only notes the caller can read.
- **Name capture.** Any user with write access could create a note named like someone else's; its own name beat the other note's alias, so the owner's next fact about that person landed in a note the squatter reads. In a team vault a name that two readable notes claim is now ambiguous: the fact goes to the user's inbox and says why.
- **`index.md` told readers what notes they can't read were about** (title and description lines). Readers now see only the lines for notes they can read, and a write can't drop the lines they can't see.
- Notes a caller can't read no longer change how a name resolves for them (no more "found" turning into "No entity" when a hidden note appears).
- An account called `owner` in a multi-user vault is no longer unrestricted; only the single-owner server has the unrestricted view.
- The Anthropic memory tool can no longer write the pinned `core.md`.
- `files read` is bounded (20 distinct files, 400 KB): a 47 KB request could produce a 175 MB reply.
- OAuth: revoking a copied refresh token's family now lasts a full refresh lifetime (it ended with the copied token's own expiry), and two servers sharing a state file no longer overwrite each other's spent-token records. The sign-in page shows where your browser is sent next and says to continue only for a connection you started.
- An access-denied message was mistaken for a version conflict (the word "shared" contains "sha") and retried five times, each with a full re-index, under the global write lock.

### What gets saved
- **Denial of service.** Several patterns were quadratic on text from outside: a 64 KB note took 3.7 s to render, scanning 1 MB took 48 s, 131 KB of spaces in a checkpoint froze the server for 8.7 s, and 131 KB in a todo made the PreCompact hook take 15 s. All linear now.
- **One set of rules for every way in.** `<private>` spans, secrets and text that reads as instructions to an AI were handled by `remember` only; the `files` tool, the memory tool and LLM rewrites skipped two of the three. They share one check now, and so does `about=` (it becomes a file name and an index line). The injection screen also reads text the way recall will show it, so a comment, a link alias or an invisible character no longer hides a phrase.
- **The secrets guard** now catches the JSON, markdown, table and "the password is …" forms of a password, opaque `Bearer` and `Basic` headers, GitLab, Google OAuth, Slack and Discord webhook and bot tokens, Telegram, Twilio, Mailgun, Azure, Shopify, PyPI and DigitalOcean tokens, `STRIPE_KEY=`-style environment lines, PINs and `redis://:password@host`. It blocks fewer ordinary notes by mistake (`tokens: 128000`, `token_url=…`, paths and URLs, `Secretary: …`, and random 13 to 19 digit ids: card numbers now need a real issuer prefix and length).
- Hooks: a prompt containing U+2028 is no longer dropped, `<private>` text and half-cut tokens never reach a checkpoint, the compactor's summary is screened and can't forge one of our section headings, and text can't close the `<githippo-context>` wrapper from inside.

### Setup, git and your machine
- **A public backup is refused.** githippo asks GitHub anonymously whether the backup remote is publicly readable; the background push, `githippo sync` and `githippo doctor` refuse a public repository. `GITHIPPO_ALLOW_PUBLIC_BACKUP=1` overrides.
- A symlink pushed into a vault (by a collaborator or a compromised remote) is no longer read as a note; a folder inside another repository no longer pulls or pushes that repository; git runs with literal pathspecs (a `[s]ecret` in a path no longer globs onto a denied note's history), never prompts, and ignores global signing and hook settings for vault commits (`GIT_SIGN=1` still signs); `git pull --rebase` works with no identity configured.
- `setup` keeps your `EMBEDDINGS` and `VAULT_DIR`, honours `CLAUDE_CONFIG_DIR`, and makes `~/.githippo` private to you. `doctor` no longer starts the 500 MB model download; a failed install backs off for an hour (`githippo warm` retries); tokens from `config.json` are kept out of the install's environment; adopting an existing folder keeps its `.gitignore`.
- On the GitHub store, notes over 1 MB (the contents API returns them empty) are refused instead of being overwritten by the next append.

### Docs and CI
A shorter README that says what is and isn't measured, with the benchmark and configuration tables moved to `docs/`; `SECURITY.md`; a Dependabot config (weekly pull requests for npm and GitHub Actions); the release job's `mcp-publisher` is pinned to a version and checksum.

### Upgrading
- Re-run the installer, or `npm i -g github:AnxovatomicaES/githippo#v3.9.2`; Claude Desktop users download the new `.mcpb` below; plugin users update the plugin.
- `setup` is idempotent and does not rewrite hook entries that already exist, so installs made before 3.9.2 keep their old hook timeouts. To get the shorter per-prompt timeout, run `githippo uninstall && githippo setup`.
- Behaviour changes to know about: in a team vault a fact about an ambiguous name waits in your inbox; `files read` takes at most 20 paths; the `files` tool and memory tool now refuse instruction-like text and strip `<private>` spans; remote sessions still can't be asked to confirm (set `GITHIPPO_CONFIRM=strict` on the server to refuse instead).

### Known limits
- The injection screen is a heuristic for the common phrasings: a paraphrase gets through. The secrets guard is a backstop, not DLP: a secret that is base64-encoded, split across words or URL-encoded gets through.
- Hooks and the MCP entry call `githippo` from `PATH`; if it isn't there, a hook does nothing. Use an absolute `VAULT_DIR` (a relative one makes a vault per working directory). `npm i -g github:…` ignores the lockfile, so dependencies resolve within their ranges at install time.
- Registering an OAuth app under any name is open by design (that is how claude.ai connects); the sign-in page now shows the redirect host, which is the mitigation.
- Whether memory improves answers, or saves tokens net, is not yet measured: the evaluations that would show it need an API key and have not been run. The `.mcpb` bundle is not code-signed yet.
