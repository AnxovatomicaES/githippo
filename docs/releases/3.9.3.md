## 3.9.3: hooks twice as fast, and five problems found by measuring instead of reading

After 3.9.2 the work turned from reviewing code to measuring behaviour: how long the hooks take, what a question costs as memory grows, whether a changed fact survives being saved, whether a big session's checkpoint still says where it stopped. Each of the five problems below was found by a measurement, fixed, and given a test that fails on 3.9.2. **If you use recall for weeks on end, upgrade: the first one made answers slowly get worse.**

### Fixed
- **Usage learning could push the right answer out of first place.** Memory that keeps being handed to Claude gets a small ranking boost. It was applied after rank fusion, where scores differ by only 1 to 3% between neighbouring ranks, so a note that had merely been shown before beat a rank-1 match: in a test, the right note ranked first for 100% of rare-codename questions on a fresh vault and for 35 to 40% after a few dozen queries. The boost is now applied to each list's raw score before ranking (up to +40% on the keyword score, +10% on the semantic score), so it only reorders results that were nearly tied. With no usage data nothing changes.
- **`remember` silently dropped facts that changed one word.** In keyword mode, 6 of 12 facts that differed from a known one by a single meaningful word ("dark" / "light", "automatically" / "manually", "weekly" / "monthly", "avoid" / "use", "hour" / "day", "read" / "write") were answered "already known" and never saved. A pair where each side has a content word the other lacks is now saved and flagged as a possible update, never called a duplicate (0 of 12 dropped), and `maintain` lists such a pair as a possible contradiction. The cost: a reworded fact that only swaps a synonym ("hosted on" / "runs on") is now saved as a flagged near-duplicate instead of being merged.
- **A big session's checkpoint lost "Where it stopped".** A checkpoint has a budget of about 900 tokens, and for a realistic large session the text was cut at the limit, which removed the last sections first: the resume point, the errors, the commands. Compaction only happens in big sessions, so this hit the feature's main use. The checkpoint is now built at decreasing detail until it fits: the earlier summary, commands, older requests and finished tasks go first; the goal, the open tasks and where it stopped are kept; tasks that don't fit are counted; a long path is clipped from the left so its file name survives.
- **The per-prompt hook injected memory for unrelated prompts.** On 1,000 to 10,000 notes about a sixth of ordinary coding prompts ("refactor the parser to use async iterators", "rename the variable foo") got about 220 tokens of memory, because words the vault has never seen were ignored when judging the match. They now count against it: none of 20 unrelated coding prompts is given memory at 1,000 or 10,000 notes, and all 40 planted questions still fire with the right note.
- **A regression in 3.9.2: reading a transcript with one huge line was quadratic.** The U+2028 fix re-scanned its buffer for every chunk; one 30 to 60 MB line (a pasted file or image) took 0.9 to 3 seconds, more on a loaded machine. It is linear again (37 ms).

### Faster
- **Hooks and the status line start in about 60 ms instead of about 125.** `githippo hook prompt` runs before every prompt and `githippo statusline` runs constantly, but the command loaded the whole MCP server (SDK and zod, about 85 ms) at start-up. Now only the commands that need it load it. On the development laptop (median of 12; `node` alone takes 38 ms): status line 124 to 58 ms, `hook prompt` 127 to 59 ms, `hook session-start` 131 to 64 ms. `githippo bench` prints your own numbers.

### Also fixed
- A note that isn't valid UTF-8 (Latin-1 from an old editor, an Obsidian import) used to be decoded with replacement characters, and the next append or edit wrote that damage back over your file. Such a note is now reported and skipped, never read or rewritten; convert it to UTF-8 to use it.
- A relative `VAULT_DIR`, `CACHE_DIR` or `OAUTH_STATE_FILE` made a separate vault in every folder a process started in. From `config.json` it now means "inside `~/.githippo`"; from the environment, relative to where you typed it.
- `POST /token` with a non-string `resource` answered 500; it is an `invalid_target` now.
- Hooks assumed `/`-separated paths (the project name, the "files no longer exist" check, the steering text); they accept either separator.

### What it costs, measured
`npm run bench:scale` builds vaults of 100 to 30,000 synthetic notes and asks planted questions (a full name plus a topic, or a rare codename plus a topic hundreds of notes share). The context a question costs stays flat, about 550 tokens as a recall pack and about 265 as a brief, while loading the whole memory grows from 7 thousand to 2 million tokens, and the planted fact reached the pack every time. It is a stress test of keyword mode on synthetic notes (names and rare codenames are the easy case): it says nothing about paraphrases, real notes or whether answers improve. It is also how the ranking bug above was found.

### Platforms
CI now also runs the suite on macOS (Node 22), where it passes. Windows is not supported yet: about 19 tests fail there, mostly because the tests assume POSIX; `docs/platforms.md` says what fails and why, and a weekly informational workflow tracks it.

### Upgrading
- Re-run the installer, or `npm i -g github:AnxovatomicaES/githippo#v3.9.3`; Claude Desktop users download the new `.mcpb` below; plugin users update the plugin. Hook entries that `setup` already wrote are not rewritten (it is idempotent), so installs made before 3.9.2 keep their old hook timeouts: `githippo uninstall && githippo setup` refreshes them.
- Behaviour changes to know about: a fact that swaps one content word for another is saved and flagged instead of being treated as a duplicate; a big session's checkpoint may omit commands, older requests and finished tasks (counted, not silently dropped); the per-prompt hook fires less often on prompts the vault doesn't know the words of; a note that isn't UTF-8 is skipped with a warning.

### Known limits
Everything listed for 3.9.2 still applies (the injection screen is a heuristic, encoded secrets get through, hooks call `githippo` from `PATH`, the `.mcpb` is unsigned, and whether memory improves answers is not yet measured: those evaluations need an API key and have not been run). New in this release: the GitHub Actions the release job uses were bumped to their latest majors (checkout 7, setup-node 7, cache 6), so this is the first release built with them.
